# 开发流程

## 标准步骤

1. 阅读 `Codex.md`、相关需求和现有开发日志。
2. 检查工作区状态，确认已有修改，不覆盖无关工作。
3. 将任务拆分为数据、服务、界面和验证四类。
4. 小步实现，每完成一个行为就进行编译或针对性测试。
5. 更新相关文档和当天开发日志。

## 代码标准

- 遵循 Swift API Design Guidelines。
- 视图负责展示和用户事件，业务规则放在服务或规划器中。
- 避免强制解包；可恢复错误应提供用户可理解的状态。
- 只在复杂规则前添加简短注释，不解释显而易见的代码。
- 新增内容字段时同时更新模型、仓库、界面和测试。

## 内容维护

- 日常词汇优先覆盖问候、出行、餐饮、购物、工作和社交。
- 例句应自然、短小、适合口语，不包含敏感或过时表达。
- 每个词条至少包含两个相关搭配和一个核心用法说明。
- 新内容加入后检查重复 ID、重复英文和空字段。

## 完成定义

代码已编译、相关测试通过、关键界面可操作、文档已同步、开发日志已更新。
